# DGhostMarket — предложение по редизайну первого экрана

Статус: **предложение, не внедрено.** Перед реализацией нужно согласование по каждому разделу. Цены, скидки и акции в примерах условные. Для показа брать только реальные лоты из `/api/skins`. Пример «AWP Printstream −25%» не использовать, пока такого предложения нет на витрине.

---

## 1. Публичный сайт (dghostmarket.uz)

### Проблемы

- На телефоне логотип занимает почти весь первый экран (скриншот 360 px: ~260 px из ~800). Заголовок и кнопка «Открыть в Telegram» видны только после прокрутки или у самого низа.
- Реальные лоты есть на главной (блок `<!--LOTS-->`, его строит `tools/build.py`), но они ниже первого экрана. Посетитель не видит сразу, что здесь продают и почём.
- Нет строки доверия с проверяемыми цифрами. Текст «Оплата удерживается площадкой…» верный, но абстрактный.

### Предложенная структура первого экрана (мобильный)

```
[шапка: логотип-значок · RU/UZ/EN]
Покупайте и продавайте скины CS2 за сумы        ← H1 без изменений
[Открыть в Telegram]  [Открыть в браузере]      ← кнопки без изменений
┌ лот ┐ ┌ лот ┐                                ← 2×2 реальных лота,
└─────┘ └─────┘                                   цена в сумах, «−N% к рынку» если есть
┌ лот ┐ ┌ лот ┐
└─────┘ └─────┘
Строка доверия: N сделок завершено · гарант удерживает оплату · продавцы с KYC
```

- Логотип-иллюстрация уменьшается до ~120 px справа от заголовка или уходит ниже. Сам рисунок не меняется.
- Лоты берутся в том же порядке, что и витрина мини-аппа (`showcaseRank` в `app-catalog.js`). Нужно перенести эту формулу в `tools/build.py`, иначе сайт и мини-апп будут показывать разное.

### Затрагиваемые компоненты

- `src/index.html` — разметка hero, CSS.
- `tools/build.py` — отбор и порядок лотов, новый маркер `<!--HERO_LOTS-->`.
- `i18n.json` — тексты строки доверия на трёх языках.

### Нужные реальные данные

- Число завершённых сделок. Сейчас открытого эндпоинта нет: нужен публичный счётчик в боте, например `/api/stats/public`. Это изменение API, поэтому отдельно согласуется.
- Признак KYC у продавцов уже есть (`seller_verified`).
- Если счётчика нет, строка доверия выводится без цифр, только с фактами.

### До / после

- **До:** логотип на весь экран → H1 → кнопки → (прокрутка) → лоты.
- **После:** H1 → кнопки → 4 лота → строка доверия → логотип и остальное без изменений.

### Плюсы и риски

- **Плюсы:** посетитель за 1–2 секунды видит товар и цену; LCP становится текстом или картинкой лота, а не логотипом.
- **Риск:** узнаваемость бренда на первом экране снижается — нужно согласовать размер логотипа.
- **Риск:** картинки лотов приходят с серверов Steam. Если Steam тормозит, первый экран будет пустоватым. Нужны заглушки фиксированного размера (они уже есть: `width`/`height`).

**Сложность:** средняя, 1–2 дня. Без счётчика сделок — 1 день.

## 2. Мини-апп — главный экран

### Проблемы

- Промо-баннер (`.promo-slide`, `min-height:168px` плюс отступы) и блок «Шаблон лота» отодвигают первые карточки. На 360×640 видна примерно одна строка карточек.
- Слайды баннера общие («Продавай…», монета) и не ведут к конкретному товару.
- Переключатель «Шаблон лота: Компакт / Крупная» стоит прямо над каталогом. Это настройка вида: пользуются ей редко, а место она занимает каждый раз.

### Предложение

- Баннер ниже примерно вдвое: ~84 px. Одна строка заголовка, кнопка справа, иллюстрация меньше (`coin-512.webp` уже подходит).
- Первый слайд — «Выгода дня»: реальный лот с наибольшим `−N% к рынку` из тех, что уже считаются в карточках (`market_price_uzs`). Если такого лота нет, слайд не показывается. Скидка не придумывается.
- «Компакт / Крупная» перенести в ряд фильтров или сортировки, иконкой рядом с сортировкой. Выбор по-прежнему сохраняется в `dg_card_layout`.

### Затрагиваемые компоненты

- `app-home.js` — слайды баннера.
- `app.css` — `.promo-slide`.
- `index.html` — место `.layout-bar`.
- `app-catalog.js` — `applyCardLayout`; логика не меняется, только место кнопок.
- `app-i18n.js` — тексты.

### Нужные реальные данные

- Лоты с `market_price_uzs` — уже приходят из API.
- Без новых полей.

### До / после (360×640)

- **До:** шапка → баннер 168 px → «Как купить за 3 шага» → «Шаблон лота» → вкладки → 1 ряд карточек.
- **После:** шапка → баннер ~84 px «Выгода дня» → вкладки с иконкой вида → 2 ряда карточек.

### Плюсы и риски

- **Плюсы:** товары видны сразу.
- **Риск:** продавцы, которые привыкли к переключателю, могут его не найти — нужна подсказка один раз.
- **Риск:** «Выгода дня» зависит от качества рыночной цены. Лоты без рыночной цены в слайд не попадают.

**Сложность:** низкая или средняя, ~1 день.

## 3. Страницы цен — «Покрутить в 3D»

### Как сейчас устроено

- 3D-модели лежат за Worker `3d.dghostmarket.com`. Список доступных скинов — в `models/index.json` (его читает `loadModelIndex()` в `app-3d.js`; строит `build-index.sh`).
- Встраиваемый просмотрщик уже есть: `embed.html?key=…&skin=…&float=…&seed=…&lang=…`. Ключи и разрешённые домены проверяет бот; демо-ключ `demo` уже используется на странице `/3d-api/`.
- Ошибки: если модели нет, `embed.html` показывает сообщение, а не пустой экран. Это стоит проверить на 2–3 скинах без модели перед внедрением.

### Предложение

- `tools/build.py` при сборке скачивает `models/index.json`. Страница скина получает кнопку «Покрутить в 3D» **только если модель есть**.
- По нажатию кнопка открывает `<iframe loading="lazy">` с `embed.html`. До нажатия ничего тяжёлого не грузится, и скорость страницы цены не страдает.
- Для сайта нужен отдельный ключ, привязанный к домену `dghostmarket.uz`, не `demo`.

### Затрагиваемые компоненты

- `tools/skins.py` — разметка кнопки.
- `tools/build.py` — загрузка индекса моделей.
- `.github/workflows/build.yml` — шаг `curl` индекса.
- Ключ виджета в боте.

### Риски

- Сборка зависит от доступности `3d.dghostmarket.com`. Если индекс не скачался, кнопки просто не выводятся, как это уже сделано с данными Skinport.

**Сложность:** низкая, ~0,5 дня плюс выдача ключа.

## 4. Браузерная версия — витрина без обязательного входа

### Как сейчас устроено

- `app-web.js`: без сессии и без флага `dg_web_guest` при загрузке сразу показывается экран входа (`openGate()`). Каталог открывается после «Смотреть как гость».
- Каталог берётся из открытого `/api/skins` — его уже без авторизации использует и сборщик сайта. Покупка и другие действия требуют сессии (`init_data`).

### Предложение

- Не открывать `openGate()` автоматически. Показывать витрину сразу, а вход запрашивать при «Купить», «В корзину», «Хочу», «Продать» и в разделах «Сделки» и «Профиль».
- Кнопка «Войти» в шапке остаётся.

### Что проверить перед внедрением

- Все действия, требующие сессии, на сервере уже проверяют `init_data`. Изменение касается только интерфейса, права доступа не меняются. Нужно пройтись по списку эндпоинтов и убедиться, что ни один не полагается на «гость не дойдёт до кнопки».
- Интерфейс должен ловить ответ сервера «нет сессии» и открывать экран входа, а не показывать ошибку.

### Плюсы и риски

- **Плюсы:** на один экран меньше до товара; меньше отказов у посетителей из поиска и рекламы.
- **Риск:** меньше пользователей войдут сразу — меньше подписок на уведомления бота. Это компромисс, решение за владельцем.

**Сложность:** низкая, ~0,5 дня, плюс аудит эндпоинтов ~0,5 дня.

| Раздел | Сложность | Нужны новые данные/API | Меняет композицию |
|--------|-----------|------------------------|-------------------|

3. баннер мини-аппа;
4. первый экран сайта.
